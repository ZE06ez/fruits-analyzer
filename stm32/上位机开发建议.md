## 2. 电机命令与参数含义(速查)

### 2.1 二进制帧(推荐自动化使用)
```
AA 55 CMD PLEN [载荷] CRCH CRCL   (CRC16-CCITT-FALSE 覆盖 CMD..载荷,小端序)
```

| CMD | 名称 | PLEN | 载荷(小端 float) | 参数含义 |
|---|---|---|---|---|
| 0x01 | MOVE_ABS | 8 | deg, rpm | **绝对角度°**(相对上电零点),转速 rpm |
| 0x02 | MOVE_REL | 8 | deg, rpm | **相对当前角度**;deg 可负=反转 |
| 0x03 | STOP | 0 | - | 减速停止 |
| 0x04 | SET_POS_PID | 12 | Kp,Ki,Kd | 位置环 PID(默认 8/0.2/0,一般不改) |
| 0x05 | SET_VEL_PID | 8 | Kp,Ki | 速度环 PID(默认 0.8/8) |
| 0x06 | SET_PROFILE | 12 | max_rpm,acc,dec | 速度上限/加速度/减速度(pps/s) |
| 0x07 | SET_CONFIG | 4 | ppr | 每转脉冲数(**必须=驱动器 P-00**,默认 1600) |
| 0x08 | QUERY_STATUS | 0 | - | 立即回一帧 STATUS |
| 0x09 | SET_ORIGIN | 0 | - | 当前位置清零(对好 1 号孔后发) |
| 0x0F | RESET | 0 | - | 软复位 |

**应答 0x80 ACK**:PLEN=2 = [回显CMD, result]。result:0=OK 1=CRC错 2=未知 3=参数超限 4=忙。
**0x81 STATUS**:PLEN=14 = [state, err, pos_deg, vel_rpm, tgt_deg];state:0空闲 1运动 2减速停 3到位。

### 2.2 ASCII 文本(人工验证/调试)
| 命令 | 参数 | 回执 |
|---|---|---|
| `EN` | - | `EN_OK` |
| `MOVE deg rpm` | 相对角度°,转速(≤500) | 执行完 `MOVE_OK`;未EN/参数错/忙 → `MOVE_ERR` |
| `STOP` | - | `STOP_OK` |

### 2.3 参数约束
- 转速:0.5 ~ **500 rpm**(>500 被拒 result=3)
- 角度:±100000°;**22.5° = 100 脉冲**(1600ppr),精度 0.225°
- 22.5° 单步实测 **~89ms**(默认 acc40000/dec60000),远超流程 300ms/200ms 窗口
- **断电重启位置归零** → 开机人工对好 1 号孔后发 `SET_ORIGIN`(0x09)或 ASCII 暂无对应(用二进制)

## 3. 按采集流程的电机调用时序

### 3.1 正向逐片(滤光片 1→10,9 次 22.5°)
```
电脑: 发 MOVE_REL(22.5, 100)   ← 相对正转 22.5°
       等 ACK(result=0)          ← 命令已被接受
       等 state=3(到位)或 MOVE_OK  ← 旋转完成(约 90-150ms)
       等 300ms(转轮稳定,流程第15步)
黑白相机拍照(电脑自己控制)
```

### 3.2 反向回位(9 次 -22.5°)
```
电脑: 发 MOVE_REL(-22.5, 100)   ← 相对反转 22.5°(deg 为负)
       等 ACK → 等 state=3 → 等 200ms
```

### 3.3 上位机主循环伪代码(Python 风格)
```python
def move_22_5(direction):            # direction: +1 正 / -1 反
    ack = send_cmd(MOVE_REL(direction*22.5, 100))   # §4 带重试
    if ack is None or ack.result != 0:
        raise CommError("电机命令失败")
    wait_status_state(3, timeout=1.0)  # 等到位;ASCII 模式则等 "MOVE_OK"
    time.sleep(0.30 if direction>0 else 0.20)  # 等转轮稳定

# —— 对应《关键步骤.txt》电机部分 ——
```

## 4. 通信可靠性设计(必做)



### 4.2 ACK 超时重试(推荐实现)
```python
def send_cmd(frame, timeout=0.2, retries=3):
    for attempt in range(retries):
        ser.write(frame)
        resp = wait_for_ack(timeout)       # 等 0x80 ACK 帧
        if resp is None:                   # 超时:链路丢帧 → 重发
            continue
        if resp.result == 0:  return resp  # 成功
        if resp.result == 4:               # BUSY:电机运动中,等到位再重发
            wait_status_state(3, 1.0); continue
        raise ProtocolError(f"result={resp.result}")
    raise CommError("重试耗尽")
```

### 4.3 ASCII MOVE 的重试
等 `MOVE_OK`/`MOVE_ERR`,500ms 超时未回 → 重发(最多 3 次)。
**注意**:MOVE_OK 之后 MCU 才允许下一条 MOVE;以 `MOVE_OK` 同步,不要用固定延时。

### 4.4 物理层建议(降低丢包根源)
1. **检查 TTL 线接触**(本机多次因线松动丢包)——排针/杜邦线插紧,必要时焊点/端子
2. 信号线用**双绞/屏蔽线**,与 48V 电机线、驱动器**分开走线**(EMI 是运动中丢包主因)
3. TTL 模块与板子**可靠共地**
4. 若仍频繁,波特率可降到 57600(需同步改固件 `drv_uart.c` 的 BaudRate)

## 5. 状态机与错误处理

| 现象 | 含义 | 上位机处理 |
|---|---|---|
| ACK result=4 | 电机运动中,命令被拒 | 等 state=3 后重发(不是故障) |
| ACK result=3 | 参数超限(转速>500 等) | 查参数,报错 |
| 无 ACK | 链路丢帧 | 重试(§4) |
| STATUS state=2 长期不结束 | 停止中 | 继续等 |
| 断电重启 | 位置归零 | 重发 SET_ORIGIN 后再采 |
